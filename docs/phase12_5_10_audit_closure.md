# 12.5–12.10 — виправлення після аудиту

## Що виправлено

| Пункт | Результат |
|---|---|
| 12.5 | Початкові залишки ОЗ не можна сторнувати, поки існують наступні активні операції. Сторновані залишки не входять до зносу. |
| 12.6 | Виправлено виклики API, звірку ID картки, перетини періодів, порядок місяців, обмеження сторнування та обхід через загальний журнал. |
| 12.7 | Виправлено перевірку відкритого періоду; рухи серіалізуються з іншими операціями ОЗ і перевіряють хронологію. |
| 12.8 | Захищено джерело поліпшення від сторнування; виправлено невідомий ID та права сторнування; додано перегляд залишкового строку. |
| 12.9 | Не можна сторнувати переоцінку до сторнування наступних операцій, зокрема вибуття. Виправлено права сторнування. |
| 12.10 | Перевіряються дати й залежності; підтримано часткове списання та прив’язку до вже проведеного продажу. |

Операції зберігають первісні події та створюють окремі сторнування. Повторні
запити перевіряють ключ і значення запиту. Сервіси не виконують commit/rollback:
транзакцією володіє API. Проведення й сторнування використовують спільні
бухгалтерські сервіси.

## Нові поля API

### Ручний виробіток, 12.6

- Картка ОЗ: `expected_output` — очікуваний загальний обсяг, до 6 знаків після коми.
  Для вже введеної виробничої картки без плану дозволено одноразово додати тільки
  це поле через оновлення картки; подальша довільна заміна плану заборонена.
- Місячне нарахування: `actual_output` — фактичний обсяг за календарний місяць.
- Виробничий метод вимагає обидва значення. Інші методи відхиляють `actual_output`.
- Знімок плану і факту зберігається в події. Нульовий виробіток реєструється без
  нульової проводки; його можна сторнувати й повторно ввести виправлений факт.
- Сума обмежена залишком вартості, що амортизується.
- Зменшення залишкової вартості використовує річну норму; прискорений метод —
  річну подвоєну норму; кумулятивний — вагу року використання.

Формули звірено з [офіційним поясненням ДПС до НП(С)БО 7](https://zir.tax.gov.ua/main/bz/view/?id=36177&src=ques).
Це бухгалтерська амортизація; окремий податковий регістр у цей пакет не входить.

### Строк після поліпшення, 12.8

`new_remaining_life_months` — нова кількість **залишкових** місяців починаючи
з наступного місяця після поліпшення. Поле дозволене для поліпшення введеного
в експлуатацію ОЗ. Зберігаються попередній строк і база нового графіка.
Попередні нарахування не переписуються. Сторнування відновлює попередній строк
після сторнування залежних нарахувань.

### Часткове вибуття та продаж, 12.10

- `disposal_fraction`: частка поточної вартості, більше 0 і не більше 1; за
  замовчуванням 1 (повне вибуття). Вартість, знос і ліквідаційна вартість
  списуються пропорційно, з округленням до копійок.
- Часткове вибуття залишає попередній статус картки. Знос списаної частини
  виключається з подальших розрахунків. Сторнування повертає знімок вартості.
- `sale_source_line_id`: рядок кредиту доходу оригінального проведеного журналу
  продажу тієї самої компанії. Система зберігає його суму як `sale_net_amount`.
  Джерело має вже відображати належні дохід, розрахунки та ПДВ.
- Один рядок продажу відповідає одному активному вибуттю; для кількох ОЗ у
  продажу потрібні окремі рядки доходу. Рядок не може повторно списувати рахунок ОЗ.
- Вибуття формує лише списання вартості та зносу; повторних доходу, боргу або
  ПДВ не створює. Продаж не можна сторнувати до сторнування вибуття.

## Міграції та перевірки

Чотири нові ревізії після `739f64c150c1`: `8fa12510c001`–`8fa12510c004`.
Старі застосовані ревізії не змінюються. Відкат відмовляється видаляти нову
історію виробітку, часткових продажів чи перегляду строку.

Перевірки охоплюють конкурентні повтори, сторнування, порядок подій, API,
виробіток, ліквідаційну межу, частковий продаж без повторного доходу,
перегляд строку та upgrade/downgrade зі збереженням даних.

Тест вибуття переведено на окрему випадкову схему. Загальну регресію запускаємо
в окремій тимчасовій базі. Початковий аудит до цього виправлення створив
34 тестові компанії: точний список звірено, записи скопійовано в локальну
резервну копію і видалено разом лише з їхніми початковими тестовими даними.

Це завершення backend/API виправлень 12.5–12.10. Звіти та звіряння ОЗ (12.11)
і загальний аудит завершення блоку (12.12) залишаються наступними пунктами.
