# Блок 13: виконання утримань у момент виплати

Статус 15.10.2026: розрахунковий компонент реалізовано; фінансове виконання
ще не активоване. Цей документ не є актом завершення пункту 2.

## Підтверджені обмеження

Наявні D1–D4 об'єкти залишаються технічними попередніми перевірками.
Жоден з їхніх прапорців не замінюється на True для обходу перевірок.
Позитивний історичний PayrollDeductionResult без підтвердженого походження
не повинен автоматично ставати дозволеним.

Для операційного виконавця потрібні: перевірена підстава, чинне погоджене
правило, підтверджений отримувач, сума та дата конкретної виплати,
доступна після податків база з урахуванням захищених доходів, застосовні
межі й документована черговість. Проводка перенесення заборгованості
не є сама по собі підтвердженням банківського перерахування.

## Розрахунок в межах виплати

`payroll_deduction_payment_allocator.py` працює в цілих копійках:

- перевіряє суми, унікальність інструкцій і доступний ліміт;
- застосовує черги в установленому переданому порядку;
- пропорційно розподіляє недостатню суму між вимогами однієї черги;
- не перевищує індивідуальну межу; перерозподіляє вільний залишок;
- детерміновано розподіляє останні копійки;
- повертає застосовану й незастосовану суми без створення фінансових записів.

Джерело черговості, бази й меж повинен перевіряти операційний сервіс;
клієнтський preview не може бути таким доказом. Алгоритм не присвоює
юридичну черговість лише на підставі назви категорії.

## Нормативні джерела для інтеграції

Переглянуто 15.10.2026:

- [Закон 1404-VIII, статті 69–73](https://data.rada.gov.ua/ogd/zak/perv/text/d457901.htm):
  база після обов'язкових утримань, межі при кожній виплаті,
  спеціальні правила для допомог і захищені доходи, перерахування та звітування.
- [КЗпП, статті 127–129](https://data.rada.gov.ua/ogd/zak/perv/text/d23605.htm):
  підстави й обмеження відрахувань.

Стаття 46 Закону регулює розподіл виконавцем; не можна автоматично
прирівнювати довільний технічний priority ERP до юридично підтвердженої черги.
Для аліментів окремо потрібні документована сума, гарантований мінімум,
заборгованість та застосовна індексація; 70% — не універсальна ставка.

## Перевірки й наступне рішення

13 unit-тестів пройдено, включно з 1000 детермінованими наборами для
перевірки збереження сум, меж і черговості. Реальні утримання, проводки,
борги отримувачам і звіряння перерахувань цими тестами не підтверджуються.

Для подальшої реалізації прийнято повний обсяг: аванси та всі часткові
виплати. Це потребує інтеграції з PayrollAdvance та місячним зарахуванням. Виплати з чинними підставами
не можна пропускати мовчки; непідтримані сценарії мають відхилятися явно.


## Захист виплат — 15.10.2026

Виплата перевіряє чинні на її дату інструкції працівника в компанії,
включно з інструкціями іншого його договору. Перевірка виконується при

результат. Чинна інструкція поки зупиняє нове проведення з явним поясненням;
ця заборона не є реалізацією фактичного утримання.
